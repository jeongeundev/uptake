**범용 리뷰는 내장 `/code-review <base>`가 한다**(Standards + Spec + 코드 스멜). 이 스킬은 그것이 구조적으로 못 보는 **uptake CRITICAL 축**만 맡는다. 겹치지 마라 — 표준 준수·스펙 대조·리팩터링 제안을 여기서 반복하지 마라.

인자는 비교 기준점(`main`, `HEAD~5`, 브랜치명). 없으면 `main...HEAD`. `git diff <base>...HEAD`로 변경분을 잡는다. 비어 있으면 즉시 종료한다.

## 경계

- **리뷰만 한다.** 고치지 마라. phase를 만들지 마라. 파일로 남기지 마라 — 판정은 이 대화로 보고한다.
- 코드를 쓴 세션이 그 코드를 검토하면 자기채점이다(ADR-008). **독립 세션에서** 돌린다.

## 1. 검증 축 (Agent 도구, `subagent_type: Explore` — 읽기 전용)

> 이 스킬은 **Claude Code 전용**이다. 독립 서브에이전트 병렬 실행에 의존하므로 Codex에서는 돌지 않는다.

서브에이전트 2개를 **한 응답에서 동시에** 띄운다. 각각에 diff와 `AGENTS.md`·`docs/ADR.md`를 넘긴다.

**축 A — 성공 위장 (ADR-008).** 이 프로젝트에서 가장 위험한 결함이다.
- green이 증명으로 취급된 곳: 음성 테스트(심은 위반이 red로 잡히는지)가 **없는데** 통과를 근거로 삼은 곳.
- 게이트 red를 **exit code로 판정**한 곳. 인프라 오류(`gate-error`·timeout·설정 오류)를 "위반을 잡았다"로 계산한 곳.
- 실패가 삼켜진 곳: 예외를 먹고 성공 경로로 흐르거나, 부분 실패가 전체 성공으로 보고되는 곳.
- 테스트가 실제 대상 대신 mock을 검증해 파이프라인이 미검증으로 남은 곳.

**축 B — provenance (ADR-009) + 태도 (ADR-006).**
- 추출·생성 결과에 **실재하는 소스 경로**가 달렸는가. resolve되지 않는 경로를 근거로 쓴 곳.
- 신뢰할 수 없는 repo 내용이 **데이터가 아니라 프롬프트 지시**로 취급된 곳.
- 규범적 단정("이게 정답")이 서술적 서술(사실 + 트레이드오프)을 밀어낸 곳.

각 finding: `severity`(critical/major/minor/nit) · `file:line` · `tldr` · `fix`. **인용이 resolve되지 않으면 그 finding은 리뷰어가 스스로 폐기한다.**

## 2. 반박 검증 (오탐 제거)

critical·major finding은 **전부** 검증한다. 사용자가 내장 `/code-review` 결과를 붙여넣었다면 그것도 같은 절차로 검증한다.

검증 서브에이전트(`Explore`)에게:

> 이 finding이 **틀렸음을 입증하라.** 인용된 코드를 직접 읽어라. 다음 중 하나면 기각이다:
> 경로·라인이 실재하지 않는다 / 인용 코드가 주장과 다르다 / 이미 다른 곳에서 처리된다 /
> 이 변경 범위 밖의 기존 동작이다 / 재현 시나리오가 성립하지 않는다.
> 반박에 실패하면 confirm하고 근거(파일:라인)를 대라.

기각된 것은 보고에서 뺀다. 기각 건수는 집계로 남긴다.

## 3. 보고 (대화로)

판정: critical ≥ 1 → **Blocked** / (critical 0, major ≥ 1) → **Changes Requested** / 그 외 → **Approve**

```
## uptake 검증 축 판정: {Approve | Changes Requested | Blocked}
🔴 {n} · 🟠 {n} · 🟡 {n} · ⚪ {n}   (검증 통과 {confirmed}/{raw}, 기각 {rejected})

- 🔴 [성공위장] {file}:{line} — {tldr}
  → Fix: {수정 방향}
```

마지막에 한 줄: 범용 축(`/code-review`)을 아직 안 돌렸으면 돌리라고 안내한다.

## 원칙

- 리뷰는 **한 번** 돈다. 재리뷰 루프를 만들지 마라. 결과를 `phases/`로 되먹이지 마라.
- 근거 없는 finding은 보고하지 마라 — 오탐 하나가 진짜 결함 하나를 묻는다.
- 고칠지는 사용자가 정한다.
